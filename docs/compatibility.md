# 互換性

基準: Composer `f83588392df43d4fd027d84d26de459946ef4e80`（2.11.999-dev+source）。gocomposer は Composer の解決・lock・取得・展開・autoload 生成を Go で再実装したもので、Composer 全仕様の完全互換ではない。下記の「対応」は公式Composerとの差分比較（`scripts/compare.sh`、PHP 8.3/8.4/8.5）または固定実プロジェクト統合（`scripts/integration.sh`）で一致を確認した範囲を示す。証拠は `docs/validation/` の各実行ディレクトリ（生ログ付き）。

## 機能別の制限

- **plugin**: 実行する。プラグインのコードだけをコマンド実行中に常駐する PHP プロセスで動かし、Composer API はスタブ経由で Go に戻す（解決・lock・取得・展開・autoload は Go）。allow-plugins 判定（非対話時の PluginBlockedException、対話時の y/n/d と書き戻し）、plugin-api-version、activate/deactivate/uninstall と更新時の再読込、イベント購読（init、command、pre/post-*-cmd、pre/post-package-*、pre-operations-exec、カスタムイベント）、CommandProvider、カスタムインストーラ（LibraryInstaller 継承・非継承、download/prepare/cleanup/installCode/updateCode/removeCode の上書き）に対応。pre-file-download（processedUrl・customCacheKey・transportOptions、type=package/metadata、再試行ごとの再発火）・post-file-download・pre-pool-create（パッケージの除外・差し替えを解決に反映）を発火する。スタブ API: getLoop/HttpDownloader、DownloadManager（組込みダウンローダのサブクラス、新しい dist type 用ダウンローダの追加）、getAutoloadGenerator()->dump()、RepositoryManager とリモートリポジトリ（findPackage(s)、search、loadPackages、getProviders、createRepository、add/prependRepository）、Factory::create（別 PHP ホストでそのプロジェクトのプラグインも読込）、Factory::createHttpDownloader、Config::merge、Installer::create()->run()、Locker・local repository の操作、JSON スキーマ検証。副作用（取得・配置）は Go が行う。symfony/flex v2.11.0（実ソースを fixture 化）の extra.symfony.require、recipe の取得・適用（loopback HTTPS の recipe エンドポイントスタブ）、pack の unpack、recipes/recipes:install/recipes:update、remove を比較。fixture プラグイン 58 + plugin2 34 + flex 22 シナリオと、composer/installers・php-http/discovery・dealerdirect/phpcodesniffer-composer-installer・pestphp/pest-plugin・symfony/skeleton（実 recipe 適用まで）の実プロジェクト統合で一致。
  - サービス差し替え（第3段階）: プラグインが差し替えた PHP オブジェクトを、Composer が呼ぶ箇所で Go から呼び出す。setLoop・setDownloadManager・setArchiveManager・setAutoloadGenerator、getArchiveManager（独自 archiver の追加、archive コマンドも使用）、setDownloader による組込みダウンローダの置換（download/prepare/install/update/remove/cleanup、getFileName・processUrl・extract・getLocalChanges・getVcsReference の上書き。executeBatch の promise 連鎖と同じ順序）、AutoloadGenerator の buildPackageMap/parseAutoloads/createLoader・composer 以外への dump・独自 platform filter、setRepositoryClass とプラグイン実装のリポジトリ（解決に参加）、package/path/vcs/artifact リポジトリへの addPackage/removePackage、配列設定の Factory::create・createGlobal・createComposer・createConfig、Config の source/auth source の操作と自作 Config への merge、Installer の setAdditionalFixedRepository/setAuditConfig/getLockTransaction、Factory::create で作った Composer の dispatch、独自スキーマでの検証、HttpDownloader のリクエスト単位の TLS 設定（cafile・capath・verify_peer・クライアント証明書。allow_self_signed 時のみ proxy/peer_fingerprint を適用する Composer の分岐も再現）。post-file-download は転送の完了順に発火し（`COMPOSER_MAX_PARALLEL_HTTP` を尊重）、遅延付きの loopback スタブで完了順を決定的にして比較（plugin3-* 47 シナリオ）。
  - 明示エラー（理由）: `Installer::setPolicyConfig`（Composer の Policy クラス群を gocomposer のポリシー設定へ対応づけられない）、Factory::create で作った Composer への addListener/addSubscriber（別ホストのリスナー列に優先度を保って割り込めない）、ComposerRepository への addPackage/removePackage（遅延読込の有無で見え方が変わる差を再現できない）、createComposer の fullLoad=false（PartialComposer 未実装）、暗号化 PKCS#8 秘密鍵（Go 標準ライブラリで復号できない）、ext-rar のある PHP での rar 展開、PHP が見つからない場合。`--no-plugins` で回避可。
  - 既知の差: 差し替えた autoload 生成器はスクリプト・プラグイン用ローダーの生成には使われない。差し替えたダウンローダは `status` の変更検出では呼ばれない。`disablePlugins='local'` の Factory::create ではグローバルプラグインも無効になる。flex が出すランダムな session id は比較時に `SESSION` へ正規化。
  - 未比較・差異: validate と reinstall では command イベントを発火しない。`-vvv` の Factory デバッグログは出さない。
- **scripts**: コマンド文字列、`@php`、`@composer`、`@putenv`、スクリプト参照、PHPクラスコールバックに対応。クラスコールバックは別PHPプロセスでComposer APIのスタブ（Event/IO/Config/RootPackageの一部）を渡して実行する。スタブにないAPIを呼ぶコールバックは明示的な例外で失敗する。Laravelの `ComposerScripts::postAutoloadDump` と `artisan package:discover` は実プロジェクトで一致を確認。
- **リポジトリ**: composer（v1 inline/includes、v2 metadata-url、available-packages、providers-api、security-advisories metadata/api-url）、path、package、artifact（zip/tar/tgz、ext-zip 付き oracle で比較）、vcs/git（タグ・ブランチ・dev 版・reference、VCS キャッシュ、only-branches 等）、github/gitlab/bitbucket（API ドライバ。loopback の HTTPS スタブで比較、github-domains/gitlab-domains、非公開リポジトリと認証、レート制限）。v1 providers-url/provider-includes/providers-lazy-url（%hash% の置換、sha256 検証と不一致時の RepositorySecurityException 相当の失敗、list API、search の vendor 最適化。providers-* 30 シナリオ）。svn/hg/fossil/perforce（SvnDriver・HgDriver・FossilDriver・PerforceDriver と Util/Svn・Hg・Perforce。クライアントコマンドは Composer と同じく外部の svn/hg/fossil/p4 を実行。svn の http-basic・URL 資格情報と対話入力、secure-svn-domains、hg の認証付き URL 再試行、lock の reference 形式、root の VersionGuesser（hg/fossil/svn））。file://・ローカルパス・loopback の svnserve/hg serve/fossil server で比較（vcs-svn-*・vcs-hg-*・vcs-fossil-*・source-svn-* 等）。Perforce は p4d/p4 が自由に再配布できないプロプライエタリ製品で oracle に入れられないため、決まった応答を返す偽 p4（`testdata/compare/vcs/p4stub.sh`）で両ツールを同条件に比較し（vcs-perforce-*）単体テストで検証した。実サーバーとの比較は未実施。pear は Composer と同じ検出エラー・警告までを再現。forgejo ドライバは明示的に未対応エラー。
- **source インストール**: git・svn・hg・fossil・perforce（svn/hg/fossil/perforce はダウンロード・更新・削除・型変更、discard-changes と svn の対話 y/n/v/?、update -v のコミットログ）。git は（--prefer-source/--prefer-dist、preferred-install の文字列・パターン、dist への fallback、dist⇔source 切替、update 時の checkout、未コミット変更の検出と discard-changes true/false/stash、対話時の y/n/v/d/s/? 確認（update・remove・reinstall）を pty で比較）。フォージの HTTPS 上の git clone は git が Composer の cafile を使えないため比較対象外。破棄確認で EOF を入力すると Composer と同じく再質問を繰り返す（シナリオなし）。
- **認証**: 401/403 の非対話処理（AuthHelper::promptAuthIfNeeded）、git config からのトークン取得、GitLab CI job token、Bitbucket の access token、GitLab OAuth トークンの更新。対話入力: 401/403 の Username/Password（パスワードは非表示入力）と store-auths（true/false/prompt）による保存、GitHub トークン入力と検証・保存先選択、GitLab の Username/Password からの OAuth 取得、Bitbucket OAuth consumer の token 交換、git 認証失敗時の入力を pty で比較。パスワード・トークンが auth.json（保存を選んだ場合のみ、公式と同じ）以外の出力・キャッシュ・vendor・lock に出ないことを確認。diagnose の HTTP 取得は対話認証を行わない。トークンが stdout/stderr・キャッシュ・vendor に出ないことを -vvv を含めて確認（URL に埋め込まれた認証情報は Composer と同じく lock/installed.json に残る）。
- **ダウンロード**: http(s)/file、Basic/Bearer/GitHub/GitLab/custom-headers 認証、再試行（CurlDownloader と同じ GET のみ最大3回・待ち 0/0.1/0.5 秒、-vvv の Retrying 行）、checksum、キャッシュ（Composerと同じキー）、`http.timeout`（接続 10 秒・全体 300 秒）。curl のエラー番号は libcurl 8.14.1 の文言で 1（HTTP/0.9）・6・7・18・28・35・52・55・56・60 を Go のエラーから対応づけて再現（loopback の障害サーバーで比較、curl-*）。対応表にないエラーは番号なしで Go のエラー文を含む。壊れた HTTP/ 状態行は Go が先に検証するため HTTP/0.9 扱いになる。応答の warning/info（ResponseWarnings、packages.json・メタデータ・provider・search/list API・filter api-url・advisory API）を表示（warnings-*）。
- **アーカイブ**: zip/tar(.gz/.bz2)/単一gzip。zipの `../` は unzip と同様に除去してパッケージ内に展開し、パッケージ外を指すシンボリックリンクとシンボリックリンク経由の書き込みは拒否する（Composerより厳しい）。xz は Composer と同じく `tar -xJf`、rar は `unrar x`（失敗時は ext-rar の無い PHP と同じエラー）、zip は unzip/7z/ext-zip の選択とフォールバック・警告を Composer と同じ条件で再現（7z・unrar を入れた `-arch` イメージで比較、archive3-*）。ext-rar を持つ PHP での RarArchive 展開は RAR 形式を標準ライブラリだけで実装する規模が大きいため明示エラー。ZipArchive の CRC エラーの扱いは ext-zip 1.22.3 で無視・1.22.8 で失敗を確認し、境界は 1.22.4 と推定。
- **対話**: 入力が端末のときだけ対話モードになる（Composer と同じ isatty 判定。`-n`、`COMPOSER_NO_INTERACTION`、`-q`、非端末入力では従来どおり既定値で進む）。Symfony QuestionHelper（確認・質問・検証付き再質問・非表示入力・選択/複数選択・オートコンプリート、Ctrl-D で既定値または "Aborted."）と OSC 7501/9;4 の端末状態表示を移植。init、require（パッケージ省略時の検索・選択、dev 推奨、別キーからの移動、virtual パッケージのバージョン、類似名からの選択）、remove の別キー確認、update --interactive、run-script/exec の選択、create-project の --ask と VCS 履歴削除、allow-plugins の y/n/d/?、親ディレクトリの composer.json 利用確認、認証入力、discard-changes を、比較ハーネスの疑似端末（`tools/compare/ptyrun`、80x24、TERM=xterm）で決めた入力列を流して比較（tty-* 81 + tty-auth/tty-discard 60 シナリオ）。root 実行時の「Continue as root/super user」確認（COMPOSER_ALLOW_SUPERUSER、-n、pty での y/n/Enter、--no-plugins）を、比較コンテナを `--user 0` で動かして比較（root-*。Platform::isDocker を偽にするためコンテナの /run/.containerenv を外す）。Linux の rootless podman での root シナリオは構成上動く想定だが、この環境（macOS の podman machine）でのみ実行確認。
- **端末表示**: 非端末出力はComposerと一致を確認。OSC 7501/9;4 の端末状態表示、decorated 出力の `<href=…>` のハイパーリンク（OSC 8。TERMINAL_EMULATOR/KONSOLE_VERSION/IDEA_INITIAL_DIRECTORY による無効化を含む）、ProgressBar の上書き描画（`\e[1G\e[2K`、再描画の間引き、端末幅による切り詰め）を pty で比較（term-*）。時間に依存する途中のバー・経過時間・OSC 7501 の途中の進捗率は比較時に正規化（生出力は結果 JSON に残す）。
- **時刻依存の文言**: `show` の相対日付等は同時刻実行で一致。
- **Composer自体がPHPエラーで落ちる入力**: composer.json の require 値が配列（ConfigValidatorのTypeError）や COMPOSER_AUTH の username が数値（BaseIOのTypeError）の場合、gocomposer はクラッシュせずスキーマエラー表示/無視とする（比較では KNOWN-DIFF として記録）。
- **ResponseWarnings**: リポジトリの warning/info 応答の表示は filter api-url・advisory API の応答について未実装。
- **キャッシュ GC**: Composer と同じく files cache の GC をプロセスごとに 1/51 の確率で実行し、`COMPOSER_TEST_SUITE` で無効になる。GC はキャッシュディレクトリを作成・削除し比較結果を揺らすため、比較ハーネスは両ツールに `COMPOSER_TEST_SUITE=1` を渡す（基準SHAの Composer ではこの変数はこの GC にしか使われない）。GC 自体は単体テストで確認。
- **比較での正規化（Composer 側の非決定性）**: (1) uninstall フェーズの進捗バーは Composer の非同期 `rm -rf` が待機開始時に残っているかで「0/N」か不定形かが変わる（過去12回の oracle 実行で 11 回が不定形）。`reinstall-progress` だけ「Removing」直後のバーを不定形に揃えて比較し、gocomposer は通常の不定形を出す。(2) PHP 8.5 で Composer 自身のソース（例 `src/Composer/Util/Svn.php:318`）が出す PHP の Deprecation Notice は oracle 側 stderr からその行だけ除外する。いずれも生出力は結果 JSON に残る。
- **時刻依存のシナリオ**: show の cooldown 残り時間（「Nd Nh left」）は、oracle と gocomposer の実行が時の境界をまたぐと表示が変わりうる。
- **PHP 拡張なしでの動作**: platform 検出には PHP 実行ファイルが必要（GOCOMPOSER_PHP または PATH の php）。見つからない場合は php/ext-* を提供しない platform として扱う。
